# ตรวจเบราว์เซอร์ อุปกรณ์ และการขยาย 200%

## ผลที่ตรวจเมื่อ 31 ตุลาคม 2569

ใช้ build ของโครงการกับ Worker และ D1 local แยกทั้งหมด สร้างบัญชีทดสอบและทะเบียนจำลอง 1,000 ราย ไม่แก้ไขข้อมูลในระบบจริง

| สภาพแวดล้อม                              | ผล            | ขอบเขต                                                                                   |
| ---------------------------------------- | ------------- | ---------------------------------------------------------------------------------------- |
| Chromium 154.0.8037.57 บน Linux ซูม 200% | ผ่าน          | Browser zoom จริง ความกว้าง 1,536 เหลือ 768 CSS pixels และ devicePixelRatio เป็น 2       |
| Firefox ESR 140.12.0 บน Linux            | ผ่าน          | เข้าสู่ระบบ ทะเบียน ฟอร์มคำขอ ปฏิทินไทย ข้อผิดพลาดใกล้ช่อง PDF 1,000 ราย และรายงาน       |
| Firefox ซูม 200%                         | ผ่าน          | ตั้ง native fullZoom ของเบราว์เซอร์ ตรวจความกว้างลดครึ่งหนึ่งและ devicePixelRatio เป็น 2 |
| จอเล็กจำลอง 320×740 ใน Chromium          | ผ่าน          | Touch/viewport simulation, CPU ช้าลง 4 เท่า และ V8 old-space 128 MiB                     |
| แท็บเล็ตจำลอง 768×1024 ใน Chromium       | ผ่าน          | ทะเบียน ฟอร์ม ปฏิทิน PDF และรายงาน                                                       |
| Safari บน iPhone จริง                    | ยังไม่ได้ตรวจ | ไม่มี iPhone หรือ Safari runtime เชื่อมต่อกับเซสชัน                                      |
| Android แรมน้อยจริง                      | ยังไม่ได้ตรวจ | ไม่มีอุปกรณ์จริงเชื่อมต่อกับเซสชัน                                                       |

ไม่พบ JavaScript page error จากเส้นทางที่ตรวจ และไม่พบการเลื่อนแนวนอนระดับหน้า ตารางที่มีหลายคอลัมน์เลื่อนภายในพื้นที่ตารางได้

การจำกัด old-space เป็นการจำกัดหน่วยความจำส่วนหนึ่งของ JavaScript เท่านั้น ค่า heap limit ที่ Chromium รายงานในรอบนี้คือ 224 MiB ไม่ใช่การจำลองมือถือแรม 128 MiB หรือรับรองว่าใช้ได้บนมือถือแรม 2 GB ระบบปฏิบัติการ GPU การสลับแอป และแรงกดดันหน่วยความจำจริงยังต่างจากเครื่องทดสอบ

ผล Firefox เป็น Firefox desktop จริงในโหมด headless ไม่ใช่ Firefox Android หรือ Safari การทดสอบเหล่านี้ยังปิดรายการอุปกรณ์จริงไม่ได้

## รันทดสอบซ้ำ

ติดตั้ง dependencies และ build ก่อน:

```sh
npm ci
npm run build
npm run test:compatibility
```

คำสั่งเริ่มต้นตรวจ Chromium ที่ `/usr/bin/chromium` และบันทึก Firefox เป็น `not-run` หากไม่ได้ระบุ binary กับ geckodriver ผล JSON ภาพหน้าจอ และ PDF อยู่ที่ `/tmp/bs-sams-compatibility`

ตรวจ Firefox เพิ่มได้โดยใช้ Firefox ที่ติดตั้งในเครื่องและ geckodriver ที่รองรับ:

```sh
npm run test:compatibility -- --firefox-binary /path/to/firefox --geckodriver /path/to/geckodriver
```

หากใช้ Firefox ที่แยกไฟล์ไลบรารีไว้ ให้เพิ่ม `--firefox-library-dir /path/to/libraries` ใช้ `--only-firefox` หรือ `--only-zoom` เมื่อต้องตรวจเฉพาะกรณี และ `--output-dir <path>` เพื่อแยกผลแต่ละรอบ

Firefox ต้องใช้ shared memory ที่อนุญาตให้ renderer ทำงานได้ ในเซสชันนี้ต้องรันคำสั่งทดสอบผ่าน execution mode ที่อนุญาตส่วนนั้น จึงเปิด Firefox ได้ ไม่ได้เปลี่ยนการตั้งค่าหรือสิทธิ์ของแอป production

Chromium ใช้ zoom preference ในโปรไฟล์ชั่วคราว ส่วน Firefox ใช้ WebDriver chrome context ตั้ง native fullZoom ไม่ใช้ CSS `zoom`, pinch zoom หรือเปลี่ยน deviceScaleFactor แล้วอ้างว่าเป็น browser zoom ภาพ native zoom ของ Chromium เก็บผ่าน CDP โดยตรง เพื่อหลีกเลี่ยงปัญหาการตัดภาพของ Playwright เมื่อ browser zoom ไม่ใช่ 100%

## ตรวจต่อบนอุปกรณ์จริง

ใช้บัญชีและข้อมูลจำลองบนระบบทดสอบ บันทึกรุ่นอุปกรณ์ รุ่น OS รุ่นเบราว์เซอร์ แนวตั้งหรือแนวนอน และผลแต่ละขั้นตอน ชุดรายการต่อไปนี้เป็นงานที่ยังต้องทำ ไม่ใช่ผลผ่านแล้ว:

1. เปิด Safari บน iPhone และ Chrome บน Android แรมน้อยจริง เข้าสู่ระบบและเปิดทะเบียนที่มีข้อมูลหลายหน้า
2. เปิดและปิดเมนู หมุนจอ ตรวจชื่อภาษาไทยยาวและปุ่มที่มีข้อความหลายคำว่าอ่านได้และกดได้
3. เปิดรายละเอียดบุคคล เลือกการ์ดคำขอ ตรวจว่าหัวข้อและช่องที่ต้องกรอกไม่ถูกแถบหัวหรือปุ่มบันทึกบัง
4. เปิดปฏิทินไทย เลือกเดือนและปี ล้างวันที่ แล้วลองกรอกด้วยคีย์บอร์ดจริง ตรวจช่วงที่คีย์บอร์ดเปิดว่าช่องกรอกและปุ่มยังเข้าถึงได้
5. ทดลองส่งแบบฟอร์มที่ไม่ครบ ตรวจข้อความใต้ช่องและการพาโฟกัสไปแก้ ก่อนกรอกข้อมูลให้ถูกและบันทึก
6. ส่งออก PDF รายบุคคล เปิดไฟล์จากแอป Files/Downloads และทดสอบ PDF ทะเบียนตามขนาดใช้งานจริง
7. เปิดรายงาน เลื่อนตารางซ้าย–ขวา ตรวจว่าคอลัมน์แรกยังบอกแถวได้ และไม่มีการเลื่อนทั้งหน้าโดยไม่ตั้งใจ
8. ตั้ง page zoom 200% ใน Safari และทดสอบเพิ่มขนาดตัวอักษรของ OS แยกจากการ pinch zoom ตรวจว่าปุ่มและข้อมูลสำคัญไม่หาย
9. บนมือถือแรมน้อย ให้สลับไปแอปอื่นแล้วกลับมา ระหว่างอ่านข้อมูลและระหว่างมีร่างที่ยังไม่บันทึก บันทึกว่ามีการ reload หรือ tab discard หรือไม่ ระบบปัจจุบันยังไม่กู้คืนร่างหลัง browser ปิด

บันทึกข้อผิดพลาดพร้อมขั้นตอนทำซ้ำและภาพที่ไม่มีข้อมูลส่วนบุคคล หากยังไม่ได้ตรวจกรณีใด ให้คงสถานะยังไม่ได้ตรวจไว้
