# BS-SAMS

Ban Sadet Social Assistance Monitoring System

ระบบติดตามการช่วยเหลือผู้ประสบปัญหาทางสังคม

กองสวัสดิการสังคม องค์การบริหารส่วนตำบลบ้านเสด็จ

ระบบทะเบียนบุคคล คำขอรับการช่วยเหลือ และรายงาน ใช้ React กับ Vite สำหรับหน้าเว็บ และ Cloudflare Workers กับ D1 สำหรับ API และฐานข้อมูล

ระบบที่เผยแพร่: <https://bs-sams.omega-piammani.workers.dev>

## ความสามารถหลัก

- ส่งออกทะเบียน CSV, EXCEL และ PDF พร้อมข้อมูลบุตรหรือเด็กในความอุปการะ แยกคอลัมน์หมวดหมู่กับประเภทความช่วยเหลือ และอิงตัวกรองกับสิทธิ์ผู้ใช้
- แถวผู้ปกครองที่บันทึกข้อมูลเด็กแล้วมีปุ่ม +/− ข้างชื่อ กดเพื่อแสดงหรือหุบตารางคำนำหน้า ชื่อ นามสกุล และอายุของเด็กใต้แถว โดยแยกตามคำขอ
- คำขอประเภทเงินสงเคราะห์เด็กในครอบครัวยากจนเพิ่มบุตรหรือเด็กในความอุปการะได้หลายคน โดยกรอกเลขบัตรประชาชน คำนำหน้า ชื่อ นามสกุล วันเกิด อายุคำนวณอัตโนมัติ และความพิการ ไม่เก็บสถานภาพหรือโทรศัพท์มือถือของเด็ก ข้อมูลผูกกับคำขอ กู้คืนพร้อมร่างและแสดงใน PDF รายบุคคล หากเปลี่ยนประเภทคำขอ ข้อมูลเด็กเดิมยังคงอยู่ การลบข้อมูลเด็กที่บันทึกแล้วต้องมีสิทธิ์ลบและยืนยันก่อนบันทึก ตรวจด้วย `npm run test:children` หลัง build
- จัดเก็บทะเบียนบุคคล ค้นหา กรอง เรียงลำดับ และแบ่งหน้าจาก D1
- ก่อนเพิ่มบุคคล ระบบเตือนชื่อที่ตรงหรือใกล้เคียงร่วมกับวันเกิด/เบอร์โทร และเลขบัตรที่ตรงกัน โดยเปิดเผยเฉพาะข้อมูลที่มีสิทธิ์ดู ต้องตรวจทะเบียนเดิมหรือยืนยันว่าเป็นคนละบุคคลก่อนเพิ่ม
- แยกคำขอเป็นรายครั้ง จัดกลุ่มตามหมวดหมู่และประเภท แต่ละหมวดมีปุ่มเพิ่มคำขอของตัวเอง และล็อกหมวดเมื่อสร้างแล้ว
- คำขอใหม่หนึ่งรายการบันทึกความช่วยเหลือได้หนึ่งครั้ง พร้อมแสดงวันที่ได้รับการช่วยเหลือ ข้อมูลเก่าที่มีหลายครั้งยังคงอยู่ แต่เพิ่มประวัติในคำขอเดิมไม่ได้
- เมื่อบันทึกประวัติการช่วยเหลือใหม่สำเร็จ ระบบเปลี่ยนสถานะคำขอนั้นเป็น **ช่วยเหลือแล้ว** อัตโนมัติ โดยไม่เปลี่ยนสถานะของคำขออื่น
- รายละเอียดความช่วยเหลือไม่บังคับกรอก ผู้มีสิทธิ์แก้ไขและลบสามารถลบคำขอหรือประวัติที่บันทึกแล้วได้ หลังยืนยันและกดบันทึกข้อมูล
- ทะเบียนบุคคลมีถังขยะและกู้คืนได้ ผู้ดูแลระบบเท่านั้นสามารถลบรายการในถังขยะอย่างถาวรได้ทุกเมื่อ โดยยืนยันก่อนลบและมีประวัติการทำรายการ การลบคำขอจะลบประวัติความช่วยเหลือภายในคำขอนั้นเมื่อบันทึก
- แสดงวันที่เป็นวัน/เดือน/ปี พ.ศ. พร้อมปฏิทินไทย แต่ส่ง API และเก็บใน D1 เป็น `YYYY-MM-DD` ค.ศ.
- รายงานตามปีงบประมาณไทยหรือช่วงวันที่ แยกหมวดหมู่และประเภทความช่วยเหลือ พร้อมตารางรายหมู่บ้านและรายละเอียดรายเดือน แต่ละส่วนมีปุ่มส่งออกของตัวเอง
- ไฟล์รายงานรายหมู่บ้านแสดงทุกหมวดหมู่และทุกประเภทที่มีคำขอในช่วงวันที่เลือก ซ่อนหมู่บ้านที่ไม่มีข้อมูล และจัดยอดรวมให้ตรงคอลัมน์จำนวนคน
- ส่งออก CSV, EXCEL และ PDF ตามตัวกรองและสิทธิ์ รวมถึง PDF รายละเอียดผู้ประสบปัญหารายบุคคล
- ผู้ดูแลจัดการบัญชี สิทธิ์ หมู่บ้าน ประเภทความช่วยเหลือ โลโก้ และประวัติการทำรายการได้
- ธีมใช้ชุดสี More4 โดยใช้ม่วงเข้มเป็นสีหลัก และใช้สีแยกหมวดหมู่กับสถานะในแบบฟอร์มและกราฟ

## เริ่มพัฒนาในเครื่อง

เตรียมเครื่องมือตามงานที่จะทำ:

| เครื่องมือ                              | ใช้สำหรับ                                                 |
| --------------------------------------- | --------------------------------------------------------- |
| Node.js 24 ขึ้นไป และ npm               | ติดตั้ง dependencies, พัฒนา, build และรันสคริปต์          |
| Python 3 พร้อมโมดูล `sqlite3`           | Unit test ของเครื่องมือสำรอง และตรวจการกู้คืน             |
| Chromium ที่ `/usr/bin/chromium`        | Integration test, compatibility test และ performance test |
| Poppler ที่มี `pdftotext` และ `pdfinfo` | ตรวจเนื้อหาและจำนวนหน้า PDF ในชุดทดสอบ                    |
| Firefox และ geckodriver ที่รองรับกัน    | ทดสอบ Firefox เพิ่มเติม เป็นตัวเลือก                      |

Wrangler ติดตั้งผ่าน `npm ci` อยู่แล้ว ไม่ต้องติดตั้งแยกแบบ global

### ติดตั้งและเตรียมฐานข้อมูล local

รันคำสั่งจากโฟลเดอร์ repository:

```sh
npm ci
npm run db:migrate
npm run build
```

ข้อมูล D1 local อยู่ใน `.wrangler/state` และแยกจากฐานข้อมูล Cloudflare จริง ใช้ข้อมูลจำลองในการพัฒนาและทดสอบ

### สร้างบัญชีผู้ดูแล local

ใช้ Bash รับรหัสผ่านผ่าน terminal โดยไม่เขียนรหัสผ่านลงประวัติคำสั่ง:

```bash
read -rs -p 'Initial admin password: ' ADMIN_PASSWORD
export ADMIN_PASSWORD
npm run bootstrap
unset ADMIN_PASSWORD
```

บัญชีเริ่มต้นชื่อ `admin` และต้องเปลี่ยนรหัสผ่านเมื่อเข้าสู่ระบบครั้งแรก รหัสผ่านต้องมี 8–128 ตัวอักษร พร้อมตัวพิมพ์ใหญ่ A–Z ตัวพิมพ์เล็ก a–z ตัวเลข และเครื่องหมายหรือสัญลักษณ์พิเศษ เช่น `!` หรือ `@` ตัวอักษรภาษาไทยอย่างเดียวไม่นับเป็นอักขระพิเศษ

`npm run bootstrap` รองรับเฉพาะฐานข้อมูล local หากมีบัญชี `admin` อยู่แล้ว คำสั่งนี้จะไม่เปลี่ยนรหัสผ่านเดิม ระบบไม่มีบัญชีเริ่มต้นพร้อมรหัสผ่านใน source code และไม่มีการสมัครบัญชีสาธารณะ

### เปิดระบบ

```sh
npm start
```

เปิด <http://localhost:8787> เพื่อใช้ Worker กับหน้าเว็บที่ build ไว้ เมื่อแก้ frontend ให้รัน `npm run build` ใหม่

หากต้องการให้หน้าเว็บอัปเดตระหว่างพัฒนา ให้เปิดอีก terminal แล้วรัน:

```sh
npm run dev
```

เปิด URL ที่ Vite แสดง โดยปกติคือ <http://localhost:5173> และเปิด Worker พอร์ต 8787 ค้างไว้ Vite ส่งคำขอ `/api` ไปยัง Worker นี้

## ตรวจสอบก่อนส่งงาน

```sh
npm run format:check
npm test
npm run build
npm run test:children
npm run test:integration
npm run test:duplicates-drafts
npm run test:idle-session
npm run test:submission-channels
npm run test:channel-dashboard
npm run test:channel-filter
npm run test:logout
npm run test:draft-status
```

Integration test เปิด Worker และสร้างฐานข้อมูล D1 ชั่วคราวของตัวเองโดยใช้พอร์ตว่าง ไม่ต้องเปิด `npm start` ก่อน และไม่ใช้ฐานข้อมูลพัฒนา เมื่อจบจะหยุด Worker และลบฐานข้อมูลทดสอบ

ชุดทดสอบตรวจการเข้าสู่ระบบ การเปลี่ยนรหัสผ่านและเพิกถอน session สิทธิ์เจ้าหน้าที่ แบบฟอร์มและปฏิทินไทย คำขอและการช่วยเหลือ การลบและกู้คืน การแก้ไขพร้อมกัน รายงาน และไฟล์ส่งออกจริง รวมถึงหน้าจอ desktop และ mobile ภาพตรวจสอบและไฟล์ส่งออกทดสอบอยู่ใต้ `/tmp`

ชุดทดสอบเฉพาะด้าน:

| คำสั่ง                        | สิ่งที่ตรวจ                                                                                                                          |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `npm test`                    | กติกาข้อมูล การนับคนแยกหมู่บ้านและประเภท การซ่อนหมู่บ้านว่าง และ PDF จริงที่ตรวจขอบกระดาษ การตัดคำไทย และตำแหน่งคู่หมวดหมู่กับประเภท |
| `npm run test:children`       | เด็กหลายคน วันที่ ความพิการ ร่างข้อมูล การบันทึกและเปิดใหม่ ปุ่ม +/− สิทธิ์ลบ ประวัติการลบ และไฟล์ CSV/EXCEL/PDF พร้อมข้อมูลเด็ก     |
| `npm run test:logout`         | ออกจากระบบเมื่อเครือข่ายขัดข้อง แจ้งแท็บอื่น เพิกถอน session เมื่อโหลดหน้าใหม่หลังเชื่อมต่อ และเข้าสู่ระบบใหม่                       |
| `npm run test:draft-status`   | สถานะเก็บร่างเมื่อคำตอบรุ่นก่อนมาถึงระหว่างแก้ข้อมูลรุ่นล่าสุด และตรวจข้อมูลที่เก็บจริงใน D1                                         |
| `npm run test:channel-filter` | ตัวเลือกช่องทางทั้ง 3 กลุ่ม การค้นหาและล้างตัวกรอง การแบ่งหน้า และ CSV/EXCEL/PDF ที่ตรงกับผลค้นหา บน desktop และ mobile              |

`npm test` ตรวจการเปลี่ยนอายุและปีงบประมาณตามเวลาไทย รวมถึงสร้าง PDF ที่มีหมวดหมู่ครบทั้ง 7 หมวดเพื่อตรวจว่าข้อความอยู่ภายในขอบกระดาษ ใช้ Poppler ตรวจว่าคำไทยไม่แยกพยัญชนะกับสระ และหมวดหมู่เริ่มตรงกับประเภทของตัวเองแม้ชื่อประเภทยาวหลายบรรทัด

ตรวจเฉพาะการส่งออกและรูปแบบ PDF ได้ด้วย:

```sh
node --test tests/registry-export.test.js tests/report-export.test.js tests/pdf-text.test.js tests/pdf-layout.test.js
```

หากรูปแบบโค้ดไม่ผ่าน ให้รัน `npm run format` แล้วตรวจ diff ก่อนส่งงาน

### ตรวจเบราว์เซอร์และการขยาย 200%

หลัง build แล้ว รัน:

```sh
npm run test:compatibility
```

ค่าเริ่มต้นตรวจ Chromium ที่ซูม 200% จริง จอเล็กจำลอง 320×740 ที่จำกัด CPU และ JS heap และแท็บเล็ตจำลอง 768×1024 หากต้องการตรวจ Firefox ให้ระบุ binary กับ geckodriver:

```sh
npm run test:compatibility -- --firefox-binary /path/to/firefox --geckodriver /path/to/geckodriver
```

ผลอยู่ใน `/tmp/bs-sams-compatibility` หากไม่ระบุ Firefox ชุดทดสอบจะบันทึกว่าไม่ได้ตรวจ Firefox ผลบน Linux หรือจอจำลองไม่แทน Safari/iPhone และ Android แรมน้อยจริง ดู [ขอบเขตผลตรวจและรายการที่ต้องตรวจบนอุปกรณ์จริง](docs/device-qa.md)

### วัดทะเบียน รายงาน และไฟล์ส่งออก

```sh
npm run test:performance
```

ค่าเริ่มต้นใช้ข้อมูลจำลอง 1,000 และ 10,000 ราย ส่งออก CSV และ EXCEL ครบทุกคน และจำกัด PDF ทะเบียนที่ 1,000 รายต่อชุด ผลอยู่ใน `/tmp/bs-sams-performance`

ทดสอบ PDF ครบ 10,000 รายได้ด้วย:

```sh
npm run test:performance -- --sizes 10000 --pdf-rows 10000 --output-dir /tmp/bs-sams-performance-fullpdf
```

ชุดทดสอบใช้ D1 และ Worker ชั่วคราวแยกจากระบบจริง ผลที่วัดได้เป็นผลในเครื่องทดสอบ ไม่ใช่ SLA ของ Cloudflare ดู [วิธีวัด ผลล่าสุด และข้อจำกัด](docs/performance.md)

### ผลตรวจวันที่ 1 พฤศจิกายน 2569

ผลต่อไปนี้มาจากข้อมูลจำลองใน Worker และ D1 local แยกจากระบบจริง:

- Unit test ผ่าน 48 รายการ รวมการคำนวณอายุหลังเที่ยงคืนไทยและการเปลี่ยนปีงบประมาณวันที่ 1 ตุลาคม
- การตรวจรูปแบบโค้ดและ build ผ่าน
- Integration test ผ่าน ทั้งบัญชี สิทธิ์ ทะเบียน คำขอ รายงาน ถังขยะ และไฟล์ PDF กับ EXCEL จริง
- การตรวจข้อมูลซ้ำ การแยกสิทธิ์ร่าง การกู้คืน และการลองส่งคำขอซ้ำผ่าน
- Chromium ผ่านที่ซูม 200% จอจำลอง 320×740 และแท็บเล็ต 768×1024 ไม่พบข้อผิดพลาด JavaScript ในสถานการณ์ที่ตรวจ

ผลประสิทธิภาพรอบนี้ใช้ 3 ตัวอย่างต่อคำขอ API:

| จำนวนทะเบียน | API ทะเบียนหน้าแรก p95 | API สรุปรายงาน p95 | ส่งออก PDF 1,000 ราย |
| ------------ | ---------------------- | ------------------ | -------------------- |
| 1,000 ราย    | 23 ms                  | 65 ms              | 2.002 วินาที         |
| 10,000 ราย   | 15 ms                  | 381 ms             | 1.729 วินาที         |

PDF ทะเบียน 1,000 รายมี 50 หน้า และตรวจพบข้อมูลครบ 1,000 ราย ผลทั้งหมดผ่านเกณฑ์ของสคริปต์ รันทดสอบซ้ำด้วย:

```sh
npm run test:performance -- --sizes=1000,10000 --pdf-rows=1000 --samples=3
```

รอบนี้ยังไม่ได้ตรวจ Firefox, Safari บน iPhone หรือ Android เครื่องจริง ผล local ไม่ยืนยันความเร็วหรือการทำงานทุกเส้นทางบนระบบที่เผยแพร่

### ตรวจซ้ำวันที่ 2 พฤศจิกายน 2569

## เผยแพร่บน Cloudflare

`wrangler.jsonc` กำหนด Worker ชื่อ `bs-sams` และ binding `DB` ที่เชื่อม D1 ชื่อ `bs-sams` ไว้แล้ว โครงการนี้เผยแพร่แล้ว และไม่มีขั้นตอน deploy อัตโนมัติใน repository

### อัปเดตสภาพแวดล้อมที่ใช้อยู่

ใช้บัญชี Cloudflare หรือ API token ที่มีสิทธิ์เผยแพร่ Worker และจัดการ D1 ตรวจสอบบัญชีและ `database_id` ใน `wrangler.jsonc` ก่อนใช้คำสั่ง remote

หากใช้ API token ให้กำหนด `CLOUDFLARE_API_TOKEN` และ `CLOUDFLARE_ACCOUNT_ID` ผ่านระบบจัดการ secrets หรือ environment ของ terminal ไม่บันทึก token ลง Git

ก่อนเปลี่ยน schema ให้สร้างไฟล์สำรองและตรวจการกู้คืนตามหัวข้อ [สำรองและกู้คืนข้อมูล](#สำรองและกู้คืนข้อมูล) จากนั้นตรวจสอบโค้ดและทดสอบให้ผ่านก่อนรัน:

```sh
npx wrangler d1 migrations apply bs-sams --remote
npm run build
npx wrangler deploy
```

คำสั่ง `--remote` เปลี่ยนฐานข้อมูลจริง ส่วน `npm run db:migrate` ใช้เฉพาะ local การ deploy ใช้ไฟล์ frontend จาก `dist` จึงต้อง build ก่อนทุกครั้งที่เปลี่ยนหน้าเว็บ

หลังเผยแพร่ ตรวจ URL และ version ที่ Wrangler แสดง แล้วทดสอบเข้าสู่ระบบ เปิดทะเบียน และรายงานด้วยบัญชีที่ได้รับอนุญาต

### ตั้งสภาพแวดล้อมใหม่

สร้าง D1 ในบัญชีเป้าหมายและแก้ `database_id` ใน `wrangler.jsonc` ให้ตรงกับฐานข้อมูลใหม่ก่อนใช้คำสั่ง remote จัดเตรียมบัญชีผู้ดูแลคนแรกผ่านกระบวนการที่ปลอดภัยของหน่วยงาน เนื่องจาก bootstrap script นี้สร้างได้เฉพาะบัญชี local

## บัญชีและสิทธิ์

ผู้ดูแลกำหนดสิทธิ์ดู เพิ่ม แก้ไข ลบ และส่งออกให้เจ้าหน้าที่ พร้อมกำหนดหมู่บ้านที่เข้าถึงได้ API ตรวจสิทธิ์ข้อมูลบุคคลและการส่งออกตามหมู่บ้าน ส่วนข้อมูลสรุปบนหน้ารายงานแสดงทั้งตำบล

ผู้ใช้เปลี่ยนรหัสผ่านหรือออกจากระบบผ่านเมนูชื่อผู้ใช้ด้านบน การเปลี่ยนรหัสผ่านและการรีเซ็ตโดยผู้ดูแลเพิกถอน session ทุกอุปกรณ์ และต้องเข้าสู่ระบบใหม่ รหัสชั่วคราวบังคับเปลี่ยนก่อนเริ่มใช้งาน

การกดออกจากระบบกลับหน้าเข้าสู่ระบบทันที แม้คำขอไปเซิร์ฟเวอร์ขัดข้อง หาก localStorage ใช้งานได้ แท็บอื่นของบัญชีเดียวกันจะออกจากระบบด้วย หากส่งคำขอไม่สำเร็จ session ฝั่งเซิร์ฟเวอร์ยังไม่ถูกเพิกถอนจนกว่าจะเชื่อมต่อและเพิกถอนสำเร็จ หรือหมดอายุ การโหลดหน้าใหม่หลังเชื่อมต่อจะตรวจสถานะออกจากระบบที่เก็บไว้และส่งคำขอเพิกถอนอีกครั้ง

Checkbox จดจำการเข้าสู่ระบบให้อายุ session สูงสุด 30 วัน หากไม่เลือกจะใช้ session cookie และอายุสูงสุด 8 ชั่วโมง บัญชีที่ต้องเปลี่ยนรหัสผ่านยังใช้ session ระยะสั้นเสมอ Cookie เป็น HttpOnly และ SameSite=Strict พร้อม Secure บน HTTPS

### ออกจากระบบเมื่อไม่มีการใช้งาน

เมื่อไม่มีการขยับเมาส์ คลิก พิมพ์ สัมผัส หรือเลื่อนหน้าครบ 30 นาที หน้าเว็บจะกลับหน้าเข้าสู่ระบบทันที และส่งคำขอยกเลิก session โดยไม่แสดงคำเตือนหรือกล่องยืนยัน การเลือก **จดจำการเข้าสู่ระบบ** ไม่ยกเว้นกติกานี้

แท็บที่ใช้บัญชีเดียวกันในเบราว์เซอร์เดียวกันแชร์เวลาใช้งานล่าสุดผ่าน localStorage การรีเฟรชไม่เริ่มนับใหม่ หากเครื่องพักหรือแท็บถูกพัก หน้าเว็บจะตรวจเวลาทันทีเมื่อกลับมาใช้งาน ตัวจับเวลาเก็บเฉพาะเวลาและสถานะหมดอายุ ไม่เก็บรหัสผ่าน ข้อมูลบุคคล หรือร่างแบบฟอร์ม

หากเบราว์เซอร์ปิดกั้น localStorage ตัวจับเวลายังทำงานในหน้านั้น แต่แชร์เวลาระหว่างแท็บหรือเก็บเวลาข้ามการโหลดหน้าใหม่ไม่ได้ การยกเลิก session บนเซิร์ฟเวอร์ต้องมีการเชื่อมต่อเครือข่าย อายุ session สูงสุดที่ API บังคับยังเป็น 8 ชั่วโมงหรือ 30 วันตามตัวเลือกจดจำการเข้าสู่ระบบ

รัน `npm run test:idle-session` เพื่อตรวจการเข้าสู่ระบบ การต่อเวลาเมื่อมีการใช้งาน การออกจากระบบโดยไม่มีคำเตือน และการเพิกถอน session จริงด้วย Chromium บน Worker และ D1 local ชั่วคราว ชุดทดสอบจำลองเวลา จึงไม่ต้องรอ 30 นาที และตรวจกรณีปิดกั้น localStorage ด้วย

หน้าภาพรวมมีกราฟโดนัท **ยื่นคำร้องผ่านระบบ** แบ่งเป็น พม. CARE สีม่วง สายด่วน พม. 1300 สีฟ้า และทั้งสองช่องทางสีเขียว นับบุคคลที่มีคำขอในช่วงวันที่ที่เลือกครั้งเดียวต่อคน ผู้เลือกทั้งสองช่องทางนับเฉพาะกลุ่มสีเขียว ร้อยละคิดจากผู้ระบุช่องทางทั้งหมด ส่วนผู้ที่ไม่ได้ระบุช่องทางไม่รวมในโดนัท และไม่มีข้อความหมายเหตุใต้กราฟ

## กติกาข้อมูลและรายงาน

- เลขบัตรประชาชนไม่บังคับ ช่องกรอกรับเฉพาะตัวเลขสูงสุด 13 หลัก หากระบุต้องครบ 13 หลัก ผ่านการตรวจเลขหลักสุดท้าย และไม่ซ้ำ รวมรายการในถังขยะ
- Autofill ระบุชื่อ นามสกุล และโทรศัพท์มือถือแยกประเภท รวมถึงชื่อผู้ใช้และรหัสผ่าน ช่องเลขบัตรประชาชน วันที่ พ.ศ. และช่องที่ไม่มีประเภทมาตรฐานตั้งค่าปิดคำแนะนำ เบราว์เซอร์และส่วนขยายอาจไม่ทำตามคำแนะนำของเว็บไซต์
- วันที่ยื่นคำขอและวันที่ได้รับความช่วยเหลือต้องไม่เป็นอนาคตตามเวลาไทย วันที่ได้รับความช่วยเหลือต้องไม่ก่อนวันที่ยื่นคำขอ
- จำนวนเงินรับได้ไม่เกิน 999,999,999.99 บาทต่อครั้ง รวมยอดด้วยหน่วยสตางค์และแสดงทศนิยมสองตำแหน่ง จำนวนสิ่งของเป็นเศษส่วนได้ แต่ต้องมีหน่วยนับเมื่อระบุจำนวนเป็นบวก
- ช่วยเหลือครบเมื่อทุกคำขอมีสถานะช่วยเหลือแล้ว หากทุกคำขอยุติ จะแสดงสถานะยุติคำขอ
- ปีงบประมาณเริ่ม 1 ตุลาคม ช่วงรายงานกำหนดได้ไม่เกิน 120 เดือน และคำนวณอายุ ณ วันสิ้นสุดช่วงรายงาน
- อายุปัจจุบันและปีงบประมาณเริ่มต้นใช้เขตเวลา `Asia/Bangkok` จึงเปลี่ยนวันและปีงบประมาณตามเวลาไทย ไม่ขึ้นกับเขตเวลาของเครื่องผู้ใช้หรือเซิร์ฟเวอร์
- รายงานรายเดือนแยกจำนวนคน จำนวนคำขอ และจำนวนครั้งที่ช่วยเหลือ จำนวนคนไม่ซ้ำทั้งช่วงอาจไม่เท่าผลรวมจำนวนคนรายเดือน
- สถานะในรายงานเป็นสถานะปัจจุบันของคำขอที่ยื่นในช่วงวันที่ ไม่ใช่สถานะย้อนหลัง ณ วันสิ้นสุดรายงาน
- แบบฟอร์มเก็บร่างส่วนตัวใน D1 อัตโนมัติหลังหยุดแก้ไขประมาณ 1.2 วินาที เก็บได้ไม่เกิน 20 ร่างต่อบัญชี อายุ 7 วันนับจากเก็บล่าสุด กู้คืนได้จากหน้าทะเบียนหลังเข้าสู่ระบบใหม่ โดยไม่เก็บข้อมูลบุคคลใน localStorage/sessionStorage
- ข้อความ **เก็บร่างล่าสุดแล้ว** แสดงเมื่อข้อมูลที่กำลังแก้ตรงกับร่างที่เซิร์ฟเวอร์ยืนยันแล้วเท่านั้น หากแก้ต่อระหว่างรอส่งหรือรอคำตอบ จะแสดง **กำลังเก็บร่าง** จนเก็บข้อมูลรุ่นล่าสุดสำเร็จ
- ร่างไม่รวมเป็นทะเบียนหรือยอดรายงานจนกดบันทึกข้อมูล หากทะเบียนจริงเปลี่ยนรุ่นแล้ว ร่างเดิมเปิดอ่านได้แต่ไม่ให้บันทึกทับอัตโนมัติ
- หากคำตอบจากการเก็บร่างสูญหาย ระบบยืนยันคำขอเดิมก่อนส่งการแก้ไขล่าสุด การลองซ้ำไม่สร้างร่างเพิ่ม และการเปลี่ยนข้อมูลกลับเป็นค่าเดิมจะอัปเดตร่างด้วย
- สถานะยังเก็บร่างไม่สำเร็จหมายถึงข้อมูลล่าสุดยังไม่รับประกันว่าจะกู้ได้ ควรรอข้อความเก็บร่างสำเร็จก่อนปิดหน้า การยืนยันละทิ้งฟอร์มจะลบร่างของฟอร์มนั้นด้วย
- ข้อมูลบุคคลในถังขยะยังไม่มีวันหมดอายุและไม่ถูกลบอัตโนมัติ ผู้ดูแลต้องยืนยันลบถาวรเป็นรายรายการ
- ฟอร์มแสดงข้อผิดพลาดใกล้ช่องกรอกและพาโฟกัสไปแก้ หากอยู่ในคำขอที่ยังไม่ได้เปิด ระบบจะเปิดคำขอนั้นให้
- ตารางบนจอเล็กตรึงคอลัมน์แรก และแสดงคำแนะนำเลื่อนซ้าย–ขวาเมื่อข้อมูลล้นแนวนอน
- ปุ่มดู แก้ไข และลบในคอลัมน์จัดการเรียงแนวนอนทั้ง desktop, tablet และมือถือ

`npm run test:submission-channels` ตรวจการเลือก checkbox การเก็บร่าง การบันทึกและแก้ไข การเปิดข้อมูลหลังรีเฟรช คอลัมน์ในไฟล์ EXCEL และข้อความในไฟล์ PDF ที่ดาวน์โหลดจริงทั้งสองแบบ โดยใช้ข้อมูลจำลองบน Worker และ D1 local

บุคคลแต่ละรายเลือกช่อง **ยื่นคำร้องผ่านระบบ** ได้ทั้ง **พม. CARE** และ **สายด่วน พม. 1300** หรือเว้นว่าง ข้อมูลนี้บันทึกพร้อมทะเบียนและร่าง แสดงใน CSV, EXCEL และ PDF ทะเบียน รวมถึง PDF รายบุคคล ข้อมูลเก่าหรือรายการที่ไม่ได้เลือกจะแสดงเป็นช่องว่างใน CSV, EXCEL และ PDF

### กรองทะเบียนตามช่องทางยื่นคำร้อง

ตัวกรอง **ยื่นคำร้องผ่านระบบ** มีค่าเริ่มต้นเป็น **ทั้งหมด** และเลือกช่องทางได้ 3 กลุ่ม:

| ตัวเลือก         | ข้อมูลที่แสดง                              |
| ---------------- | ------------------------------------------ |
| พม. CARE         | ผู้เลือก พม. CARE เพียงช่องทางเดียว        |
| สายด่วน พม. 1300 | ผู้เลือกสายด่วน พม. 1300 เพียงช่องทางเดียว |
| ทั้งสองช่องทาง   | ผู้เลือกทั้ง พม. CARE และสายด่วน พม. 1300  |

กด **ค้นหา** เพื่อใช้เงื่อนไข ผลรวม จำนวนหน้า และไฟล์ CSV/EXCEL/PDF อิงตัวกรองที่กดค้นหาแล้ว ไฟล์ส่งออกครอบคลุมทุกหน้าที่ตรงเงื่อนไขและสิทธิ์ ผู้เลือกทั้งสองช่องทางไม่รวมในกลุ่มช่องทางเดียว

**ล้างตัวกรอง** คืนค่าเป็น **ทั้งหมด** ซึ่งรวมรายการเก่าหรือรายการที่ยังไม่ได้ระบุช่องทางด้วย

## ส่งออกข้อมูล

| ส่วนข้อมูล               | รูปแบบ          | ขอบเขต                                                     |
| ------------------------ | --------------- | ---------------------------------------------------------- |
| ทะเบียนผู้ประสบปัญหา     | CSV, EXCEL, PDF | ครบทุกหน้าที่ตรงตัวกรองและสิทธิ์                           |
| รายงานสรุปและรายหมู่บ้าน | CSV, EXCEL, PDF | ข้อมูลสรุปตามช่วงวันที่และสิทธิ์                           |
| รายละเอียดรายเดือน       | CSV, EXCEL, PDF | ส่งออกแยกจากรายงานสรุป                                     |
| รายละเอียดรายบุคคล       | PDF             | ข้อมูลล่าสุดที่บันทึกแล้ว พร้อมคำขอและประวัติความช่วยเหลือ |

ช่องข้อมูลที่ว่างในไฟล์ส่งออก CSV, EXCEL และ PDF จะเว้นว่าง โดยไม่เติมข้อความ **ไม่ระบุ** จำนวนเงินหรือจำนวนรายการที่เป็นศูนย์ยังแสดงค่าศูนย์ตามข้อมูลจริง ส่วนไฟล์รายงานรายหมู่บ้านซ่อนหมู่บ้านที่ไม่มีคำขอในช่วงวันที่เลือก

CSV ใช้ UTF-8 BOM และป้องกันข้อความที่เริ่มด้วยสูตร EXCEL เป็นไฟล์ `.xlsx` โดยจำนวนเงินเป็นเซลล์ตัวเลข PDF ฝังฟอนต์ Sarabun และมีเลขหน้า ทะเบียนหลายคอลัมน์ใช้ A3 แนวนอน รายงานใช้ A4 แนวนอน และรายบุคคลใช้ A4 แนวตั้ง

### ทะเบียนผู้ประสบปัญหา

CSV, EXCEL และ PDF ทะเบียนใช้คอลัมน์ตามลำดับนี้: คำนำหน้า ชื่อ นามสกุล เลขบัตรประชาชน วันเดือนปีเกิด อายุ บ้านเลขที่ หมู่ที่ โทรศัพท์ **หมวดหมู่** **ประเภทความช่วยเหลือ** **ประเภทข้อมูล** และ **ยื่นคำร้องผ่านระบบ** วันเกิดแสดงเป็น พ.ศ. เช่น `01/01/2533` บ้านเลขที่คงรูปแบบข้อความ เช่น `001/2` ไฟล์ทะเบียนไม่แสดงเลขทะเบียนภายในระบบ สถานะ หรือคอลัมน์ความพิการ

**หมวดหมู่** แสดงชื่อกลุ่ม เช่น เงินสงเคราะห์ ส่วน **ประเภทความช่วยเหลือ** แสดงชื่อที่เลือกในคำขอ เช่น เงินสงเคราะห์เด็กในครอบครัวยากจน ทั้งสองคอลัมน์อิงตัวกรองหมวดหมู่ที่กด **ค้นหา** แล้ว คู่หมวดหมู่กับประเภทที่ซ้ำในบุคคลเดียวกันแสดงครั้งเดียว หากมีหลายประเภทในหมวดเดียวกัน ชื่อหมวดจะซ้ำเพื่อให้ตรงกับแต่ละประเภท

ข้อมูลเด็กแสดงเป็นแถวต่อจากผู้ยื่นคำขอ โดยคอลัมน์ **ประเภทข้อมูล** ระบุว่าเป็นผู้ยื่นคำขอหรือบุตรหรือเด็กในความอุปการะ แต่ละแถวของเด็กมีข้อมูลส่วนบุคคล หมวดหมู่ และประเภทของคำขอที่เกี่ยวข้อง บ้านเลขที่ หมู่ที่ และโทรศัพท์ในแถวเด็กเว้นว่าง ข้อมูลเด็กไม่เพิ่มยอดผู้ยื่นคำขอในรายงานสรุป

EXCEL แยกรายการด้วยบรรทัดใหม่และปรับความสูงแถว PDF จัดหมวดหมู่กับประเภทเป็นคู่ที่เริ่มตรงกัน แม้ข้อความของคู่ก่อนหน้าจะยาวหลายบรรทัด ข้อมูลบุคคลแสดงครั้งเดียว ไม่มีเส้นคั่นระหว่างคู่ภายในบุคคลเดียวกัน และคงเส้นแบ่งระหว่างบุคคลไว้

PDF ทะเบียนแบ่งคำไทยในคอลัมน์หมวดหมู่และประเภทความช่วยเหลือ โดยไม่แยกพยัญชนะกับสระ ชื่อเงินสงเคราะห์เด็กในครอบครัวยากจนขึ้นบรรทัดใหม่ก่อนคำว่า **ยากจน**

### รายงานสรุปและรายหมู่บ้าน

ไฟล์ CSV, EXCEL และ PDF รายงานใช้ช่วงวันที่เป็นวัน/เดือน/ปี พ.ศ. เช่น `01/10/2569` ถึง `30/09/2570` แถวแยกหมวดหมู่และประเภทนับเฉพาะคำขอที่ยื่นในช่วงนั้น แม้บุคคลเดียวกันจะมีคำขออื่นอยู่นอกช่วง

| รายงาน                 | คอลัมน์ข้อมูล                                       |
| ---------------------- | --------------------------------------------------- |
| ตามประเภทความช่วยเหลือ | หมวดหมู่ → ประเภทความช่วยเหลือ → จำนวนคน            |
| รายหมู่บ้าน            | หมู่บ้าน → หมวดหมู่ → ประเภทความช่วยเหลือ → จำนวนคน |

รายงานรายหมู่บ้านแสดงทุกหมวดหมู่และทุกประเภทที่มีคำขอภายในช่วงวันที่และสิทธิ์ส่งออกของผู้ใช้ หมู่บ้านที่ไม่มีข้อมูลจะไม่ปรากฏในไฟล์ เพื่อประหยัดหน้ากระดาษ

จำนวนคนในแต่ละประเภทนับบุคคลหนึ่งครั้ง แม้ยื่นหลายคำขอประเภทเดียวกัน สำหรับรายหมู่บ้านจะแยกนับตามหมู่บ้าน หมวดหมู่ และประเภท บุคคลที่มีคำขอหลายประเภทอาจปรากฏในหลายแถว แต่ **ยอดรวมผู้ยื่นคำขอ** นับคนไม่ซ้ำทั้งช่วง จึงอาจน้อยกว่าผลรวมจำนวนคนของทุกแถว

**ผู้ได้รับความช่วยเหลือจริง** และ **จำนวนครั้งช่วยเหลือ** อิงวันที่ได้รับความช่วยเหลือ รวมถึงความช่วยเหลือของคำขอที่ยื่นก่อนช่วงรายงาน ตัวเลขยอดรวมด้านล่างจัดตรงกับคอลัมน์ **จำนวนคน**

PDF รายงานรายหมู่บ้านแบ่งคำไทยในคอลัมน์ประเภทความช่วยเหลือ และขึ้นบรรทัดใหม่ก่อน **คนพิการ** เพื่อให้วลีนี้อยู่ด้วยกัน PDF รายงานตามประเภทความช่วยเหลือไม่บังคับขึ้นบรรทัดใหม่ก่อน **ยากจน**

### รายละเอียดรายบุคคล

PDF รายบุคคลแสดงข้อมูลล่าสุดที่บันทึกแล้ว พร้อมคำขอ ข้อมูลเด็กของแต่ละคำขอ และประวัติความช่วยเหลือ รวมบ้านเลขที่และความพิการ ผู้ใช้ต้องมีสิทธิ์ดูและส่งออกในหมู่บ้านนั้น ระบบบันทึกประวัติการส่งออกและไม่ส่งออกบุคคลในถังขยะ ฟอนต์และใบอนุญาต OFL อยู่ที่ `src/assets/fonts` เครื่องมือสร้าง PDF และ EXCEL โหลดเมื่อใช้ส่งออก

## ข้อจำกัดและการดูแลข้อมูล

ระบบยังไม่รองรับนำเข้าข้อมูล แนบเอกสารหรือภาพประกอบเคส และนัดติดตาม โลโก้รองรับไฟล์ raster ไม่เกิน 200 KB

รายงานยังอ่านข้อมูลบุคคลที่ใช้งานอยู่มาคำนวณใน Worker และการส่งออกยังโหลดผลลัพธ์ที่ตรงเงื่อนไขครบชุด จึงต้องประเมินเวลาและหน่วยความจำก่อนใช้งานข้อมูลปริมาณมาก

กำหนดนโยบายสิทธิ์เข้าถึง อายุเก็บข้อมูล และตำแหน่งจัดเก็บข้อมูลให้ตรงข้อกำหนดของหน่วยงาน พร้อมทดสอบการสำรองและกู้คืน D1 ก่อนเปลี่ยน schema หรือดำเนินการกับข้อมูลจริง ห้าม commit ข้อมูลส่วนบุคคล รหัสผ่าน หรือ API token ลง repository

## สำรองและกู้คืนข้อมูล

สร้างไฟล์สำรองจาก D1 จริงด้วย:

```sh
npm run db:backup -- --remote
```

คำสั่งใช้บัญชี Cloudflare ที่มีสิทธิ์ D1 ผ่าน `CLOUDFLARE_API_TOKEN` และ `CLOUDFLARE_ACCOUNT_ID` เมื่อใช้ token ไฟล์ SQL และ manifest ที่มี SHA-256 จะอยู่ใน `backups/<timestamp>/` โฟลเดอร์นี้ไม่เข้า Git

หากสภาพแวดล้อมบล็อกโดเมนดาวน์โหลด export บน R2 ให้ใช้ API snapshot แทน โดยกำหนด `CLOUDFLARE_DATABASE_ID` ให้ตรงกับฐานข้อมูลเป้าหมายเพิ่มเติม:

```sh
npm run db:backup -- --remote --api-snapshot
```

ตรวจว่าไฟล์กู้คืนได้ด้วย path ที่คำสั่งสำรองแสดง:

```sh
npm run db:verify-recovery -- --snapshot backups/<timestamp>/database.sql
```

การตรวจนี้นำเข้าไฟล์ลง D1 local ชั่วคราว ตรวจ SHA-256 โครงสร้าง ดัชนี ข้อมูลทุกตาราง และขั้นตอนเพิกถอน session หลังการกู้คืน จากนั้นบันทึก `verification.json` ข้างไฟล์ SQL โดยไม่ย้อนข้อมูลใน D1 จริง

ไฟล์สำรองมีข้อมูลบุคคลและข้อมูลบัญชี ต้องนำไปเก็บในที่จัดเก็บถาวรที่จำกัดสิทธิ์และเข้ารหัสของหน่วยงาน ปัจจุบันยังไม่ได้ตั้งงานสำรองไฟล์ SQL ตามเวลา ที่เก็บ R2 หรือการลบไฟล์สำรองตามอายุอัตโนมัติ

ดู [คู่มือสำรอง กู้คืน และ Time Travel](docs/operations.md) ก่อนกู้คืนระบบจริง

## บุคคลที่อาจซ้ำและการกู้คืนร่าง

ก่อนเพิ่มทะเบียนใหม่ ให้ตรวจชื่อ วันเกิด และหมู่บ้านในหน้าต่างเตือน หากเป็นคนเดิมให้เปิดทะเบียนเดิม โดยร่างที่กำลังทำจะยังเก็บไว้ หากเป็นคนละบุคคลจึงยืนยันเพิ่ม ระบบตรวจซ้ำอีกครั้งที่ API และบันทึกประวัติการยืนยัน เลขบัตรที่ซ้ำยังไม่อนุญาตให้บันทึกเหมือนเดิม ไม่มีการรวมบุคคลอัตโนมัติ

ร่างอยู่ในส่วน **ร่างที่ยังไม่บันทึก** ของหน้าทะเบียน เลือกกู้คืนเพื่อแก้ไขต่อหรือลบร่างหลังยืนยัน ระบบตรวจสิทธิ์ปัจจุบันทุกครั้ง ไม่ให้ผู้อื่นอ่านร่าง แม้เป็นผู้ดูแล และไม่เปิดร่างของทะเบียนที่อยู่ในถังขยะ

ต้องใช้ migration `0004_person_drafts.sql` ก่อน deploy รุ่นนี้ Cron ล้างร่างหมดอายุทุกวันเวลา 03:00 น. ไทย และมีการล้างเมื่อใช้งาน API ร่างด้วย การหมดอายุทำให้กู้คืนไม่ได้ทันที แม้รอรอบลบจริงอยู่ ไฟล์สำรอง D1 อาจมีร่างจากอดีตตามนโยบายเก็บสำรองของหน่วยงาน

รัน `npm run test:duplicates-drafts` หลัง build เพื่อตรวจคำเตือนซ้ำ การแยกสิทธิ์ อายุร่าง การแก้พร้อมกัน การลบถาวร และการกู้คืนหลังปิดหน้าแล้วเข้าสู่ระบบจาก browser context ใหม่ รวมข้อความวันที่ที่ยังผิดรูปแบบ
