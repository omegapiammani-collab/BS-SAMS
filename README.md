# BS-SAMS

Ban Sadet Social Assistance Monitoring System

ระบบติดตามการช่วยเหลือผู้ประสบปัญหาทางสังคม

กองสวัสดิการสังคม องค์การบริหารส่วนตำบลบ้านเสด็จ

ระบบทะเบียนบุคคล คำขอรับการช่วยเหลือ และรายงาน ใช้ React กับ Vite สำหรับหน้าเว็บ และ Cloudflare Workers กับ D1 สำหรับ API และฐานข้อมูล

ระบบที่เผยแพร่: <https://bs-sams.omega-piammani.workers.dev>

## ความสามารถหลัก

- จัดเก็บทะเบียนบุคคล ค้นหา กรอง เรียงลำดับ และแบ่งหน้าจาก D1
- แยกคำขอเป็นรายครั้ง จัดกลุ่มตามหมวดหมู่และประเภท แต่ละหมวดมีปุ่มเพิ่มคำขอของตัวเอง และล็อกหมวดเมื่อสร้างแล้ว
- คำขอใหม่หนึ่งรายการบันทึกความช่วยเหลือได้หนึ่งครั้ง พร้อมแสดงวันที่ได้รับการช่วยเหลือ ข้อมูลเก่าที่มีหลายครั้งยังคงอยู่ แต่เพิ่มประวัติในคำขอเดิมไม่ได้
- รายละเอียดความช่วยเหลือไม่บังคับกรอก ผู้มีสิทธิ์แก้ไขและลบสามารถลบคำขอหรือประวัติที่บันทึกแล้วได้ หลังยืนยันและกดบันทึกข้อมูล
- ทะเบียนบุคคลมีถังขยะและกู้คืนได้ การลบคำขอจะลบประวัติความช่วยเหลือภายในคำขอนั้นเมื่อบันทึก
- แสดงวันที่เป็นวัน/เดือน/ปี พ.ศ. พร้อมปฏิทินไทย แต่ส่ง API และเก็บใน D1 เป็น `YYYY-MM-DD` ค.ศ.
- รายงานตามปีงบประมาณไทยหรือช่วงวันที่ แยกตารางรายหมู่บ้านและรายละเอียดรายเดือน พร้อมปุ่มส่งออกของแต่ละส่วน
- ส่งออก CSV, EXCEL และ PDF ตามตัวกรองและสิทธิ์ รวมถึง PDF รายละเอียดผู้ประสบปัญหารายบุคคล
- ผู้ดูแลจัดการบัญชี สิทธิ์ หมู่บ้าน ประเภทความช่วยเหลือ โลโก้ และประวัติการทำรายการได้

## เริ่มพัฒนาในเครื่อง

ใช้ Node.js 24 ขึ้นไปและ npm สำหรับการทดสอบผ่านเบราว์เซอร์ ต้องติดตั้ง Chromium ที่ `/usr/bin/chromium` และ Poppler ซึ่งมีคำสั่ง `pdftotext` กับ `pdfinfo`

### ติดตั้งและเตรียมฐานข้อมูล local

รันคำสั่งจากโฟลเดอร์ repository:

```sh
npm ci
npm run db:migrate
npm run build
```

ข้อมูล D1 local อยู่ใน `.wrangler/state` และแยกจากฐานข้อมูล Cloudflare จริง ใช้ข้อมูลจำลองในการพัฒนาและทดสอบ

### สร้างบัญชีผู้ดูแล local

ใช้ Bash รับรหัสผ่านผ่าน terminal โดยไม่เขียนรหัสผ่านลงประวัติคำสั่ง:

```bash
read -rs -p 'Initial admin password: ' ADMIN_PASSWORD
export ADMIN_PASSWORD
npm run bootstrap
unset ADMIN_PASSWORD
```

บัญชีเริ่มต้นชื่อ `admin` และต้องเปลี่ยนรหัสผ่านเมื่อเข้าสู่ระบบครั้งแรก รหัสผ่านต้องมี 8–128 ตัวอักษร พร้อมตัวพิมพ์ใหญ่ A–Z ตัวพิมพ์เล็ก a–z ตัวเลข และเครื่องหมายหรือสัญลักษณ์พิเศษ เช่น `!` หรือ `@` ตัวอักษรภาษาไทยอย่างเดียวไม่นับเป็นอักขระพิเศษ

`npm run bootstrap` รองรับเฉพาะฐานข้อมูล local หากมีบัญชี `admin` อยู่แล้ว คำสั่งนี้จะไม่เปลี่ยนรหัสผ่านเดิม ระบบไม่มีบัญชีเริ่มต้นพร้อมรหัสผ่านใน source code และไม่มีการสมัครบัญชีสาธารณะ

### เปิดระบบ

```sh
npm start
```

เปิด <http://localhost:8787> เพื่อใช้ Worker กับหน้าเว็บที่ build ไว้ เมื่อแก้ frontend ให้รัน `npm run build` ใหม่

หากต้องการให้หน้าเว็บอัปเดตระหว่างพัฒนา ให้เปิดอีก terminal แล้วรัน:

```sh
npm run dev
```

เปิด URL ที่ Vite แสดง โดยปกติคือ <http://localhost:5173> และเปิด Worker พอร์ต 8787 ค้างไว้ Vite ส่งคำขอ `/api` ไปยัง Worker นี้

## ตรวจสอบก่อนส่งงาน

```sh
npm run format:check
npm test
npm run build
npm run test:integration
```

Integration test เปิด Worker และสร้างฐานข้อมูล D1 ชั่วคราวของตัวเองโดยใช้พอร์ตว่าง ไม่ต้องเปิด `npm start` ก่อน และไม่ใช้ฐานข้อมูลพัฒนา เมื่อจบจะหยุด Worker และลบฐานข้อมูลทดสอบ

ชุดทดสอบตรวจการเข้าสู่ระบบ การเปลี่ยนรหัสผ่านและเพิกถอน session สิทธิ์เจ้าหน้าที่ แบบฟอร์มและปฏิทินไทย คำขอและการช่วยเหลือ การลบและกู้คืน การแก้ไขพร้อมกัน รายงาน และไฟล์ส่งออกจริง รวมถึงหน้าจอ desktop และ mobile ภาพตรวจสอบและไฟล์ส่งออกทดสอบอยู่ใต้ `/tmp`

หากรูปแบบโค้ดไม่ผ่าน ให้รัน `npm run format` แล้วตรวจ diff ก่อนส่งงาน

## เผยแพร่บน Cloudflare

`wrangler.jsonc` กำหนด Worker ชื่อ `bs-sams` และ binding `DB` ที่เชื่อม D1 ชื่อ `bs-sams` ไว้แล้ว โครงการนี้เผยแพร่แล้ว และไม่มีขั้นตอน deploy อัตโนมัติใน repository

### อัปเดตสภาพแวดล้อมที่ใช้อยู่

ใช้บัญชี Cloudflare หรือ API token ที่มีสิทธิ์เผยแพร่ Worker และจัดการ D1 ตรวจสอบบัญชีและ `database_id` ใน `wrangler.jsonc` ก่อนใช้คำสั่ง remote

หากใช้ API token ให้กำหนด `CLOUDFLARE_API_TOKEN` และ `CLOUDFLARE_ACCOUNT_ID` ผ่านระบบจัดการ secrets หรือ environment ของ terminal ไม่บันทึก token ลง Git

หลังตรวจสอบโค้ดและทดสอบผ่านแล้ว รัน:

```sh
npx wrangler d1 migrations apply bs-sams --remote
npm run build
npx wrangler deploy
```

คำสั่ง `--remote` เปลี่ยนฐานข้อมูลจริง ส่วน `npm run db:migrate` ใช้เฉพาะ local การ deploy ใช้ไฟล์ frontend จาก `dist` จึงต้อง build ก่อนทุกครั้งที่เปลี่ยนหน้าเว็บ

หลังเผยแพร่ ตรวจ URL และ version ที่ Wrangler แสดง แล้วทดสอบเข้าสู่ระบบ เปิดทะเบียน และรายงานด้วยบัญชีที่ได้รับอนุญาต

### ตั้งสภาพแวดล้อมใหม่

สร้าง D1 ในบัญชีเป้าหมายและแก้ `database_id` ใน `wrangler.jsonc` ให้ตรงกับฐานข้อมูลใหม่ก่อนใช้คำสั่ง remote จัดเตรียมบัญชีผู้ดูแลคนแรกผ่านกระบวนการที่ปลอดภัยของหน่วยงาน เนื่องจาก bootstrap script นี้สร้างได้เฉพาะบัญชี local

## บัญชีและสิทธิ์

ผู้ดูแลกำหนดสิทธิ์ดู เพิ่ม แก้ไข ลบ และส่งออกให้เจ้าหน้าที่ พร้อมกำหนดหมู่บ้านที่เข้าถึงได้ API ตรวจสิทธิ์ข้อมูลบุคคลและการส่งออกตามหมู่บ้าน ส่วนข้อมูลสรุปบนหน้ารายงานแสดงทั้งตำบล

ผู้ใช้เปลี่ยนรหัสผ่านหรือออกจากระบบผ่านเมนูชื่อผู้ใช้ด้านบน การเปลี่ยนรหัสผ่านและการรีเซ็ตโดยผู้ดูแลเพิกถอน session ทุกอุปกรณ์ และต้องเข้าสู่ระบบใหม่ รหัสชั่วคราวบังคับเปลี่ยนก่อนเริ่มใช้งาน

Checkbox จดจำการเข้าสู่ระบบให้อายุ session สูงสุด 30 วัน หากไม่เลือกจะใช้ session cookie และอายุสูงสุด 8 ชั่วโมง บัญชีที่ต้องเปลี่ยนรหัสผ่านยังใช้ session ระยะสั้นเสมอ Cookie เป็น HttpOnly และ SameSite=Strict พร้อม Secure บน HTTPS

## กติกาข้อมูลและรายงาน

- เลขบัตรประชาชนไม่บังคับ หากระบุต้องผ่าน checksum และไม่ซ้ำ รวมรายการในถังขยะ
- วันที่ยื่นคำขอและวันที่ได้รับความช่วยเหลือต้องไม่เป็นอนาคตตามเวลาไทย วันที่ได้รับความช่วยเหลือต้องไม่ก่อนวันที่ยื่นคำขอ
- จำนวนเงินรับได้ไม่เกิน 999,999,999.99 บาทต่อครั้ง รวมยอดด้วยหน่วยสตางค์และแสดงทศนิยมสองตำแหน่ง จำนวนสิ่งของเป็นเศษส่วนได้ แต่ต้องมีหน่วยนับเมื่อระบุจำนวนเป็นบวก
- ช่วยเหลือครบเมื่อทุกคำขอมีสถานะช่วยเหลือแล้ว หากทุกคำขอยุติ จะแสดงสถานะยุติคำขอ
- ปีงบประมาณเริ่ม 1 ตุลาคม ช่วงรายงานกำหนดได้ไม่เกิน 120 เดือน และคำนวณอายุ ณ วันสิ้นสุดช่วงรายงาน
- รายงานรายเดือนแยกจำนวนคน จำนวนคำขอ และจำนวนครั้งที่ช่วยเหลือ จำนวนคนไม่ซ้ำทั้งช่วงอาจไม่เท่าผลรวมจำนวนคนรายเดือน
- สถานะในรายงานเป็นสถานะปัจจุบันของคำขอที่ยื่นในช่วงวันที่ ไม่ใช่สถานะย้อนหลัง ณ วันสิ้นสุดรายงาน
- แบบฟอร์มเก็บร่างในหน่วยความจำและเตือนก่อนปิดเมื่อยังไม่บันทึก ไม่มีระบบกู้คืนร่างหลังเบราว์เซอร์ปิดผิดปกติ

## ส่งออกข้อมูล

| ส่วนข้อมูล               | รูปแบบ          | ขอบเขต                                                     |
| ------------------------ | --------------- | ---------------------------------------------------------- |
| ทะเบียนผู้ประสบปัญหา     | CSV, EXCEL, PDF | ครบทุกหน้าที่ตรงตัวกรองและสิทธิ์                           |
| รายงานสรุปและรายหมู่บ้าน | CSV, EXCEL, PDF | ข้อมูลสรุปตามช่วงวันที่และสิทธิ์                           |
| รายละเอียดรายเดือน       | CSV, EXCEL, PDF | ส่งออกแยกจากรายงานสรุป                                     |
| รายละเอียดรายบุคคล       | PDF             | ข้อมูลล่าสุดที่บันทึกแล้ว พร้อมคำขอและประวัติความช่วยเหลือ |

CSV ใช้ UTF-8 BOM และป้องกันข้อความที่เริ่มด้วยสูตร EXCEL เป็นไฟล์ `.xlsx` โดยจำนวนเงินเป็นเซลล์ตัวเลข PDF ฝังฟอนต์ Sarabun และมีเลขหน้า ทะเบียนหลายคอลัมน์ใช้ A3 แนวนอน รายงานใช้ A4 แนวนอน และรายบุคคลใช้ A4 แนวตั้ง

PDF รายบุคคลต้องมีสิทธิ์ดูและส่งออกในหมู่บ้านนั้น ระบบบันทึกประวัติการส่งออกและไม่ส่งออกบุคคลในถังขยะ ฟอนต์และใบอนุญาต OFL อยู่ที่ `src/assets/fonts` เครื่องมือสร้าง PDF และ EXCEL โหลดเมื่อใช้ส่งออก

## โครงสร้างโครงการ

| ตำแหน่ง                | หน้าที่                                               |
| ---------------------- | ----------------------------------------------------- |
| `src/`                 | หน้าเว็บ แบบฟอร์ม กติกาข้อมูลร่วม และเครื่องมือส่งออก |
| `server/`              | Worker API การยืนยันตัวตน สิทธิ์ และการเข้าถึง D1     |
| `migrations/`          | Schema และดัชนี D1                                    |
| `scripts/bootstrap.js` | สร้างบัญชีผู้ดูแล local                               |
| `tests/`               | Unit test และ integration test ผ่าน Chromium          |
| `wrangler.jsonc`       | การตั้งค่า Worker, static assets และ D1 binding       |

## ข้อจำกัดและการดูแลข้อมูล

ระบบยังไม่รองรับนำเข้าข้อมูล แนบเอกสารหรือภาพประกอบเคส และนัดติดตาม โลโก้รองรับไฟล์ raster ไม่เกิน 200 KB

รายงานยังอ่านข้อมูลบุคคลที่ใช้งานอยู่มาคำนวณใน Worker และการส่งออกยังโหลดผลลัพธ์ที่ตรงเงื่อนไขครบชุด จึงต้องประเมินเวลาและหน่วยความจำก่อนใช้งานข้อมูลปริมาณมาก

กำหนดนโยบายสิทธิ์เข้าถึง อายุเก็บข้อมูล และตำแหน่งจัดเก็บข้อมูลให้ตรงข้อกำหนดของหน่วยงาน พร้อมทดสอบการสำรองและกู้คืน D1 ก่อนเปลี่ยน schema หรือดำเนินการกับข้อมูลจริง ห้าม commit ข้อมูลส่วนบุคคล รหัสผ่าน หรือ API token ลง repository
