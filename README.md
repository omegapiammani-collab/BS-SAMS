# BS-SAMS

ระบบข้อมูลผู้ประสบปัญหาทางสังคม กองสวัสดิการสังคม องค์การบริหารส่วนตำบลบ้านเสด็จ

React + Vite, Cloudflare Workers, D1. ไม่มีการ deploy อัตโนมัติ ไม่มีข้อมูลบุคคลจริงหรือรหัสผ่านเริ่มต้นใน source code

## เริ่มพัฒนาในเครื่อง

แนะนำ Node.js 24 ขึ้นไป ใช้ checkout เดิม ไม่ต้องสร้าง worktree

```sh
cd /workspace/BS-SAMS
export npm_config_cache=/tmp/bs-sams-npm
export XDG_CONFIG_HOME=/workspace/BS-SAMS/.wrangler/config
export WRANGLER_LOG_PATH=/tmp/bs-sams-wrangler.log
npm ci
npm run db:migrate
npm run build
```

สร้างผู้ดูแลระบบในฐานข้อมูล **local** ครั้งแรก โดยตั้ง `ADMIN_PASSWORD` อย่างปลอดภัยใน terminal ไม่บันทึกลงไฟล์หรือ Git:

```sh
read -rs -p 'Initial admin password (12+ characters): ' ADMIN_PASSWORD
export ADMIN_PASSWORD
npm run bootstrap
unset ADMIN_PASSWORD
npm start
```

ชื่อผู้ใช้คือ `admin` เมื่อเข้าสู่ระบบครั้งแรกต้องเปลี่ยนรหัสผ่าน ไม่มีบัญชีสมัครเอง หากมีบัญชี admin อยู่แล้ว bootstrap จะไม่เปลี่ยนรหัสผ่านเดิม

`npm start` รัน Worker พร้อมหน้าเว็บที่ build ไว้บนพอร์ต 8787 ต้อง build ใหม่หลังแก้ frontend หรือใช้ `npm run dev` อีก terminal เพื่อเปิด Vite บนพอร์ต 5173 ซึ่ง proxy API ไปยัง Worker พอร์ต 8787

D1 local อยู่ใน `.wrangler/state` และไม่ถูก commit ห้ามใช้ข้อมูลส่วนบุคคลจริงในการทดสอบ

## ตรวจสอบ

```sh
npm test
npm run build
# ต้องมี Chromium ที่ /usr/bin/chromium ไม่ต้องเปิด npm start ก่อน
npm run test:integration
```

Integration test สร้าง local D1 และ Worker ชั่วคราวแยกในแต่ละรอบ ใช้พอร์ตว่างและลบฐานข้อมูลทดสอบเมื่อจบ จึงไม่แก้ไขฐานข้อมูลพัฒนา สร้างบัญชีและข้อมูลจำลองชั่วคราวแล้วลบทิ้ง ทดสอบ login, forced password change, การเปลี่ยนรหัสผ่านด้วยตัวเองและเพิกถอน session ทุกอุปกรณ์, แบบฟอร์มบุคคล/คำขอ/การช่วยเหลือ, Excel, ถังขยะ, optimistic concurrency, สิทธิ์เจ้าหน้าที่ การแบ่งหน้าและส่งออกข้ามหน้า และหน้าจอ 1536×1024 / 390×844 ภาพ QA ถูกเขียนใต้ /tmp ไม่อยู่ใน repository

## ขอบเขต

- ทะเบียนบุคคลเดียวมีหลายคำขอ แต่ละคำขอมีประวัติการช่วยเหลือหลายครั้ง
- มีการ์ดสรุปคำขอและปุ่มไปยังส่วนบันทึก ลบรายการใหม่ที่ยังไม่บันทึกได้โดยยืนยันก่อน
- เตือนเมื่อปิดแบบฟอร์มที่แก้ไขแล้วยังไม่บันทึก ข้อมูลร่างอยู่ในหน่วยความจำเท่านั้น ไม่รองรับกู้คืนหลังเบราว์เซอร์ปิดผิดปกติ
- ประวัติคำขอและการช่วยเหลือที่บันทึกแล้วไม่ถูกลบทิ้งผ่านการแก้ไขทะเบียน ใช้สถานะยุติคำขอพร้อมเหตุผล หรือย้ายทะเบียนทั้งคนเข้าถังขยะ
- เลขบัตรไม่บังคับ หากระบุตรวจ checksum และห้ามซ้ำ รวมข้อมูลในถังขยะ
- ความพิการเลือกหลายประเภทได้ หรือไม่มีความพิการ
- รวมเงินด้วยจำนวนสตางค์ แสดงสองตำแหน่งทศนิยม รับจำนวนเงินไม่เกิน 999,999,999.99 บาทต่อครั้ง และส่งออก Excel เป็นเซลล์ตัวเลข
- วันที่ยื่นคำขอและได้รับความช่วยเหลือต้องไม่เป็นอนาคตตามเวลาไทย และวันที่ช่วยเหลือต้องไม่ก่อนวันที่ยื่น จำนวนสิ่งของแบบเศษส่วนได้แต่ต้องระบุหน่วยนับ
- สถานะคำขอและเหตุผลยุติแยกจากการช่วยเหลือสำเร็จ นับว่าช่วยเหลือครบเมื่อทุกคำขอเป็นช่วยเหลือแล้วเท่านั้น หากทุกคำขอถูกยุติจะแสดงยุติคำขอ แม้เคยได้รับความช่วยเหลือบางส่วน
- ผู้ดูแลค้นหาประวัติการทำรายการตามวันที่เวลาไทย ผู้ทำรายการ ประเภทการดำเนินการ และรหัสรายการ พร้อมแบ่งหน้าได้ ชื่อบัญชีใหม่ถูกเก็บ ณ เวลาทำรายการ
- ผู้ดูแลรีเซ็ตรหัสผ่านผ่านปุ่มแยกจากการแก้ไขสิทธิ์ ต้องยืนยันรหัสชั่วคราวซ้ำ และบัญชีที่ปิดใช้งานต้องเปิดก่อนรีเซ็ต
- การรีเซ็ตยกเลิก session ทุกอุปกรณ์ บังคับเปลี่ยนรหัสใหม่ และบันทึกประวัติในธุรกรรมเดียวกัน
- ผู้ใช้เปลี่ยนรหัสผ่านเองได้จากปุ่มใต้เมนู หลังเปลี่ยนสำเร็จต้องเข้าสู่ระบบใหม่ทุกอุปกรณ์
- ผู้ดูแลกำหนดสิทธิ์ 5 แบบและหมู่บ้านแก่เจ้าหน้าที่ ข้อมูลสรุปเห็นทั้งตำบล ส่วนข้อมูลบุคคล/ส่งออกจำกัดสิทธิ์จาก API
- ค้นหา กรองหลายเงื่อนไข เรียงลำดับ และแบ่งหน้าที่ฝั่ง D1 โหลดเฉพาะหน้าที่เปิดอยู่
- CSV และ Excel เป็นไฟล์จริง ส่งออกครบทุกหน้าที่ตรงตัวกรองและสิทธิ์ ป้องกันข้อความเริ่มด้วยสูตรใน CSV
- ปีงบประมาณไทยเริ่ม 1 ตุลาคม อายุรายงานคำนวณ ณ วันสิ้นสุดช่วงรายงาน
- เลือกช่วงรายงานเองได้ไม่เกิน 120 เดือน แยกเดือนคนละปีและเติมเดือนที่ไม่มีข้อมูล แสดงจำนวนคนแยกจากจำนวนคำขอ/ครั้งที่ช่วยเหลือ
- รายงานสรุปส่งออกเฉพาะยอดรวมตามสิทธิ์จากเซิร์ฟเวอร์ ไม่ส่งทะเบียนรายบุคคลเข้าเบราว์เซอร์ สถานะการช่วยเหลือเป็นสถานะปัจจุบันของคำขอในช่วงวันที่
- ลบแบบกู้คืนได้ บัญชีผู้ใช้และหมู่บ้านใช้การปิดใช้งานแทนลบประวัติ
- ไม่มีนำเข้าเอกสาร แนบภาพประกอบ หรือนัดติดตาม โลโก้ระบบรองรับไฟล์ raster ไม่เกิน 200 KB

## ก่อนนำขึ้น Cloudflare

ยังไม่ได้สร้าง remote D1 หรือเผยแพร่ Worker ต้องสร้าง D1 ในบัญชีที่ได้รับอนุญาต แทน `database_id` local placeholder ใน `wrangler.jsonc` แล้วใช้ migration แบบ remote และจัดเตรียมผู้ดูแลคนแรกผ่านช่องทางที่ปลอดภัย Bootstrap script ใน repository นี้รองรับเฉพาะ local เท่านั้น

ต้องตรวจสอบข้อกำหนดการจัดเก็บข้อมูลอ่อนไหวของหน่วยงานและนโยบายตำแหน่งจัดเก็บข้อมูลก่อนใช้ข้อมูลจริง รวมถึงสำรอง/กู้คืนและกำหนดอายุเก็บข้อมูล ระบบปัจจุบันยังอ่านรายการทั้งชุดเพื่อคำนวณรายงาน เหมาะสำหรับเริ่มพัฒนาและตรวจรับงาน ต้องประเมินขนาดข้อมูลและแยก aggregation ใน SQL ก่อนใช้งานปริมาณมาก
